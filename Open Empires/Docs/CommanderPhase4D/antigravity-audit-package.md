## Lifecycle and authority maps

```text
typed player control -> owner/plan-id/revision validation -> StrategicPlanner.Controls
                    -> same existing plan pause/resume/cancel -> goal/reservation lifecycle
stale or foreign control ---------------------------> reject, no newer-plan mutation
pending recommendation ----------------------------> no plan execution
player Confirm -> existing approval + decision policy -> planner replacement
              -> old-plan cancellation/cleanup -> new approved plan admission
```

```text
copied plan + copied health -> pure adaptation proposal / pure advisory feed
proposal or advisory ------> informational UI only, never CommandBuffer/simulation
provider interpretation ---> bounded intent/recommendation, never lifecycle action
material adaptation ------> player approval -> existing policy -> planner authority
```

`StrategicPipeline` construction now validates that its simulation, goal manager, and planner refer to the same context before callback binding. The host rejects pipelines tied to a different simulation before mutating host state. A same-simulation planner/goal-manager replacement remains supported.
