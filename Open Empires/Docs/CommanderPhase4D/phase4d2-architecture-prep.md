# Phase 4D.2 architecture preparation (not implementation)

Phase 4D.2 remains gated on Phase 4D.1 focused tests, compiler state, independent review, relevant Commander regression, and boundary check. These notes capture read-only source findings before 4D.1 freezes; reread its final APIs before writing the 4D.2 design/plan.

- `StrategicPlan` already owns typed plan identity, owner, status, and current milestone. `StrategicMilestone` owns typed status, child-goal IDs/counts, requirements, and reservation IDs. `CommanderGoal` distinguishes resource, prerequisite, construction, production, and blocked states. The private `StrategicPlanner.childGoalLinks` mapping is the trusted place to copy *per-plan* child-goal health; do not infer a blocker by parsing `OutcomeMessage`, `StatusReason`, or reservation conflict text.
- `StrategicContextBuilder` already copies detached, fog-safe owned economy/population/production and visible aggregates, but only nonterminal plans. Terminal health needs an explicit plan-ID lookup/projection. Owned producer count does not establish unit-specific available capacity; worker allocation does not prove income rate or eligible idle workers.
- Prefer a primitive-only snapshot keyed by owner, plan ID, creation tick, and observed simulation tick, with typed plan/milestone status, completed/total milestones, child-goal statuses/counts, resource current/available/reserved/required amounts, population/cap, and bounded owned-production counts. Add a more specific blocker label only when a typed source proves it. Keep deterministic rendering separate from projection.
- Report explicit waiting immediately. Resource gathering is expected waiting, not a stall or failure. If a no-progress threshold is necessary, compare stable plan/milestone/progress markers over simulation ticks and document/test the exact boundary; do not use wall time, frames, or a second authoritative timeout. Current planner retry is 30 ticks; tactical evaluation/retry/blocked timeout are 15/150/1800 ticks.
- Required 4D.2 test design includes nonmutation, no advancement/provider call, deterministic repeated snapshots, structured resource/population waiting, paused/terminal states, snapshot mutation isolation, fog invariance, owner/reset replacement, and stale snapshot rejection as *current*. A focused PlayMode resource-wait → gather → healthy transition is the integration seam.

Risk: current generic `Blocked` does not prove “no worker,” and `WaitingForPrerequisite` does not by itself distinguish housing from age. Neither a string explanation nor elapsed ticks may be promoted into that diagnosis. Add typed observation plumbing only if the required classification cannot be made truthfully from existing state.
