## Required host semantics

- Recognize exactly `pause strategy`, `pause current strategy`, `resume strategy`, `resume current strategy`, `cancel strategy`, `cancel current strategy`, `strategy status`, `current strategy status`, with invariant whitespace/case normalization and one consistent optional terminal punctuation rule. Reject mixed/extended/abbreviated lifecycle-looking inputs as controls; they must not reach a provider or become commands. Route before tactical/strategic provider calls and before pending recommendation mutation.
- The trusted local host player ID comes from the initialized Commander/Conversation and must equal planner/plan owner. Raw text and provider outputs never supply owner identity. Bare text action requires exactly one owned nonterminal active plan. No plan → no active plan; >1 → explicit ambiguity result and no mutation.
- A successful pause/resume/cancel applies the core `StrategicPlanControlRequest` through `StrategicPlanner.ApplyControl`. Status is a copied detached observation, no reservation or plan mutation; multiple plans may be listed by ID. Cancelling/pausing/resuming invalidates pending/in-flight interpretation with the existing bridge generation/cancellation mechanism so late provider output cannot resurrect pending state. `clear memory` does not change an authoritative plan.
- Add small plan status, Pause, Resume, Cancel controls to existing panel without redesign. If multiple plans are active, a bounded selector cycles displayed plan IDs. Capture plan ID, owner, creation tick, and revision at *display/arming time*. A click must apply the captured token only if the same `strategicPipeline` instance and `runtimeGeneration` remain. Do not recapture a new plan under an old button state. Update displayed state from planner status/milestone events or an equivalent deterministic refresh.
- Cancel UI requires a separate, clearly labeled two-click confirmation bound to the *same captured plan revision*. Any plan revision/identity change, reset, or host replacement disarms it. Approval and cancel must not share a target. Text `cancel strategy` is itself an intentional full-form player action; do not route it through a provider.
- Reset/Initialize/InitializeStrategic/OnDestroy clear selected/armed host control state and detach any event subscriptions. A callback captured before reset must not target a new planner even when plan ID, created tick, owner, and revision numerically repeat.
