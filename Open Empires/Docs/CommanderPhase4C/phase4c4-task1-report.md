## Independent-review Tower timing fix

The review identified that a paid Tower foundation was discounted from the quote and submission budget but a relative BuildStructure goal was formed only at Fortifications. If that foundation completed during Economy/Production, the goal requested two further Towers and Fortifications reserved 600 wood, not the quoted 300. CommanderPlanner completes against `BuildStructureGoal.TargetTotal` and recovers an existing foundation before placing another; therefore the stable target is the completed-Tower count captured at **plan submission** plus two. The turtle plan now owns that absolute target. Only turtle's Tower goal creation derives a relative request count from the frozen target and current completed count; zero remaining skips goal creation. Only turtle's Tower milestone computes its current cost from that target minus completed and already-funded foundations. This leaves the existing goal manager, tactical goal classes, executor, commands, simulation, and legacy plans unchanged.
