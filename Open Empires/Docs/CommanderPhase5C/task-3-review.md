## Actionable findings

1. **[P1] An idle exact subject can complete without an observed native command endpoint.** `Assets/Scripts/AI/Commander/CommanderPlanner.cs:306-347` gates only on `simulation.CurrentTick > CommandIssuedSimulationTick`, then uses `unit.SimPosition` as the endpoint when `HasPath` is false. If the buffered MoveCommand is not processed but an exact subject is already on/within its validated slot (or is moved there by an unrelated order), the next simulation tick captures that idle position and returns `Completed`; `FinalDestination` is neither read nor tied to this request in that branch. `DistantIdleSubject_CannotCompleteUnprocessedNativeMovement` covers the far-away case only. Require affirmative post-issue native processing/request-affine receipt for **each** exact ID before accepting any idle position as completion; add the near-slot unprocessed/replacement-order counterexample. This violates the brief's actual-native-endpoint and unrelated-order completion condition, even though the subject set itself remains exact.

2. **[P2] Preflighted slots are not always the positions native movement uses.** `CommanderPlanner.cs:274-295,323-327` validates and later requires proximity within two world units of unscaled slots. `Assets/Scripts/Core/GameSimulation.cs:3189-3216` scales each non-anchor formation offset by `unit.Radius / cachedUnitRadius` and may scatter it before pathfinding; `Assets/Scripts/Core/SimulationConfig.cs:31-35` gives ordinary radius 0.4, cavalry radius 0.55, and formation scatter 0.8. For a cavalry slot more than about 5.3 units from slot zero, scaling alone can move the legal native target more than two units from the validated slot. A legitimate native route can then be reported as “stopped short,” and the actual scaled target was never actor-aware/path/fog validated. The six-unit fixture uses radius 0.4 and near slots, so it cannot establish this case. Validate the actual native formation objective (or construct a command immune to this transform) and test a larger mixed-radius exact group. This is a concrete native-contract mismatch; occurrence depends on formation geometry.

3. **[P2] A required causal form still bypasses the owned-task fact route.** `Assets/Scripts/AI/Commander/CommanderTacticalStatusSnapshot.cs:115-123` recognizes causal queries only when they contain the listed action words or a catalog unit/building name. The preparation's example **“What happened to the six units?”** contains neither; `IsStatusQuestion` at `:113-114` also misses it. `Assets/Scripts/AI/Commander/Phase4A/CommanderChatUI.ReadOnlyQuestions.cs:18-20,42-57` therefore sends no tactical snapshot and can fall back to model explanation despite an unambiguous current exact-result task. Expand the bounded task/actor-reference detection without turning generic economic `why` into unrelated army status; test this exact phrasing and absent/ambiguous variants. The current named-Spearmen and arrival tests do not cover it.
