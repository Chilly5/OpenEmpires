## Disposition of the original findings

1. **Unprocessed/replacement endpoint false completion — resolved.** `Assets/Scripts/Core/GameSimulation.cs:3220-3242` publishes a per-unit result from the ordinary native Move processing path. `Assets/Scripts/AI/Commander/CommanderGoalManager.NativeMove.cs:7-29` accepts it only for the same runtime, exact subject, and original issued command box; later subject commands mark the request replaced at `:32-47`. `Assets/Scripts/AI/Commander/CommanderPlanner.cs:349-395` now requires every exact actor's receipt and rejects missing processing, partial/no-path, and replacement before testing arrival. The idle/no-path `SimPosition` fallback that caused the P1 finding is gone. The new near-slot-unprocessed, partial-path, same-endpoint unrelated Move, and unrelated Stop cases directly exercise these distinctions (`Assets/Tests/EditMode/CommanderPhase4GCapabilityTests.cs:405-529`). Missing/ambiguous replay origin fails closed; future network/replay behavior is explicitly unverified.
2. **Native radius/scatter target mismatch — resolved for this command shape.** The native snap/target calculations were extracted without changing their arithmetic (`Assets/Scripts/Core/GameSimulation.MovementObservation.cs:75-138`; `Assets/Scripts/Core/GameSimulation.cs:3094-3108,3154-3160`). Commander preflight uses that center, checks every tile in a conservative possible-scatter envelope for semantic radius, distinct coverage, actor-aware walkability, fog knowledge, and complete route, then rejects a changed connectivity snap (`Assets/Scripts/AI/Commander/CommanderPlanner.cs:257-344`). Completion compares the actual received native endpoint with that validated center/scatter bound instead of the old unscaled slot (`:367-379`). The added mixed-radius fixture checks legal distinct native endpoints and accelerated completion (`CommanderPhase4GCapabilityTests.cs:532-574`). The all-cell envelope can conservatively reject some otherwise legal formations; that is fail-closed, not the prior false-completion risk.
3. **Counted “what happened” causal question — resolved for the specified form.** `Assets/Scripts/AI/Commander/CommanderTacticalStatusSnapshot.cs:115-139,177-182` recognizes bounded numeric/one-to-twenty word counts attached to owned units and selects matching owned request groups without broadening generic economic `why`. The added tests cover “What happened to the six units?”, a nonmatching seven-unit request, and two matching owned requests that remain ambiguous (`Assets/Tests/EditMode/CommanderGrandFixStatusTests.cs:84-119`). The route remains detached/read-only; the tests assert no new goals or commands.

## Quality watchpoint, not a scoped defect

`CommanderPlanner.cs:402-407` still squares 64-bit raw deltas in `Near` without an axis guard, so arbitrary full-range `Fixed32` inputs could overflow `long` and yield a false near result. For the reviewed legitimate native path this is not presently reachable evidence of a Task 3 failure: configuration maps are at most 512 tiles (`Assets/Scripts/Core/SimulationConfig.cs:17-25`), tile centers are one world unit apart (`Assets/Scripts/Map/MapData.cs:76-81`), and the receipt endpoint/preflighted slots and ordinary paths are map-bounded. At a 512-unit separation, the sum of two squared 16.16 raw deltas is about 2.3×10^15, well below `long.MaxValue` (about 9.2×10^18). Extreme injected/out-of-map raw positions would change that assessment; they are not established by this FIX1 package. An axis guard would be prudent hardening if such positions become in scope, but this watchpoint is not a reason to reopen the bounded FIX1 gate.

The reviewed source hashes for planner, simulation, origin ledger, tactical projection, and the two new partials match the FIX1 report. The later recovery test delta and prior Farm/lease behavior were excluded as directed. Full regression, live UI/provider, rendered real-time gameplay, and multiplayer/replay validation remain separate gates.
