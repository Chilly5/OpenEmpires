# Cross-platform voice architecture and current seams

Status: binding design/source inventory, NOT delivered Web voice. Windows/Web quality/capture/gateway integration remains implementation work.

Shared game-facing route: a bounded transcription job yields plain text into one voice-session envelope, review/edit/discard, existing SubmitVoiceTranscriptAsync/SubmitMessageAsync, strict game-owned semantic validation and separate required approval, ordinary ICommand/CommandBuffer/GameSimulation. Capture/recognizer/privacy/presentation are distinct. No recognition/JS/server result grants gameplay authority.

Windows local seam: existing ICommanderAudioCapture/ICommanderSpeechToTextProvider/CommanderAudioData and VoiceInputController. Current native wrapper has blocking inference and no exposed abort; contexts must remain owned until done, while cancellation returns UI control and invalidates late results. Public ChatUI.Initialize, draft ownership and duration repair remain open. Native binary never loads in Web.

Web primary: explicit browser mic activation and consented authenticated fixed speech gateway, no mandatory WebGPU/download/isolation. Unity6000.5.9f1 documents microphone support with permission and post-stop asynchronous loadState requirements; verify that path in actual served build or justify bounded getUserMedia/recorder/worklet adapter. Actual samples/container/rate, final chunk, permission generation, page/focus/device loss and duplicate callback checks are mandatory. No system-global/background browser hotkey, no automatic startup microphone.

Optional browser-local inference: separately pinned supported model export/tokenizer/runtime in dedicated worker, capability+real inference probe, verified bounded cache, measured WASM/WebGPU and cancellation/device loss. Never silent online fallback from local-only choice. Text fallback is usability, not Web voice completion.

Gateway integration seam: existing Axum backend main router/api modules. Current player session token proves possession of an in-memory pseudonymous login, not a durable account. Auth plus exact origin/CSRF/user quotas/concurrency/global spending ceiling and operator policy are needed; current allow-any CORS is inadequate. Keep reusable service key server-only; no client URLs/models/headers choosing arbitrary upstream. Validate encoded bytes and actual decoded duration/samples before expensive work; strict safe transcript responses/dedup/cancel/TTL/no application retention.
